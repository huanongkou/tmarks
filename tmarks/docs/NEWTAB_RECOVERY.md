# NewTab 自动同步与数据恢复（协议 v2）

扩展使用 `tab/dist` 加载。服务端需要部署本次代码到 Cloudflare Pages；尚未部署新版接口时，扩展显示错误并保留本地数据，不会回退到旧版整表上传。

## 使用

- 配置原有 TMarks 地址和 API Key。API Key 需要 `bookmarks.read/create/update/delete`，或 `bookmarks.*` 权限。
- 修改后约 2 秒自动上传；后台每分钟重试失败操作并检查云端更新。浏览器关闭时不运行，重新启动后继续。
- 分组侧栏显示同步状态、待上传数量、上次成功时间，并提供「立即上传」。状态中的「查看同步设置」直接打开同步页。
- 新标签页设置 → 同步：查看错误详情、逐项处理冲突；可选择「保留本地并上传」或「采用云端」。任一未解决冲突会暂停整批上传，其他本地修改仍保留。
- 扩展设置中的普通「立即同步」也通过同一 v2 同步逻辑恢复 NewTab 数据。

同步内容：快捷方式名称、地址、备注、所在分组/文件夹、排序、在线/缓存图标、图标库备用图标和颜色；分组名称、图标、顺序；文件夹名称、图标、顺序和归属；明确执行的删除。壁纸、侧栏固定状态、当前分组、点击次数和旧网格组件为本机设置。

## 防止数据覆盖

1. 先读取云端，再按记录版本上传增量操作。新装扩展中的空列表不代表删除，不发送全量替换。
2. 本地数据和待上传操作一起写入 `chrome.storage.local`。扩展页面关闭或后台重启后仍可重试。Web Locks 协调多个页面与后台，避免旧页面覆盖新页面新增的记录。
3. 删除只产生显式删除操作。云端保留删除标记和原值，其他设备读到标记后才移除记录。删除不存在的分组/文件夹不会隐藏仍存活的网址，孤立项显示在首页。
4. 同一记录版本不一致时返回冲突。旧设备不能静默覆盖新内容、删除新内容或恢复已经删除的记录。上传期间产生的新修改会在确认后继续上传。
5. 服务端使用 D1 事务和版本条件更新，写入前保存完整旧版本。原有 `newtab_*` 表不清空、不替换。
6. 服务器或 API Key 变化时暂停同步。用户明确选择「备份本地并切换同步账户」后，先将原本地数据及待上传操作保存到 `newtab_account_backup_<时间戳>`，再读取新账户。更换同一账户的 API Key 也需要此步骤；旧待上传内容保留在备份内，不自动转移。

## Cloudflare / D1

新增接口：`GET/POST /api/tab/newtab/sync-v2`。

新增表（迁移 `0105_newtab_sync.sql`）：

| 表 | 用途 |
| --- | --- |
| `newtab_sync_state` | 每个用户的当前版本及分组、文件夹、快捷方式记录，包含删除标记 |
| `newtab_sync_history` | 每次成功修改前的历史版本，按用户和版本号保存 |

接口会幂等创建这两张表，无需通过清空旧表来升级。标准迁移流程也可执行 0105。首次读取某个用户时，从旧 `newtab_groups/newtab_folders/newtab_shortcuts/newtab_grid_items` 导入数据；没有分组或文件夹的有效网址仍可导入首页。网格中的重复网址不再重复导入。首次导入之后以 v2 状态为准，旧版本客户端对旧表的修改不会反向覆盖 v2 数据。请让需要同步的设备均使用新版扩展。

D1 单值存在容量上限，当前对云端文档采用约 1.8 MB 的保守上限；超过时明确报错，原云端数据与本地待上传内容均保留。缓存图标通常压缩到 10 KB 左右。历史版本当前不自动清理，管理员应按实际数据量监测容量，并先导出备份再制定保留策略。

历史恢复应先导出指定用户的当前 `newtab_sync_state` 与对应 `newtab_sync_history`，核对后按记录恢复。不要直接调低当前 revision；设备会拒绝旧版本，且待上传的版本关系会失效。恢复应作为新的版本提交。此代码修改未执行线上 SQL、清表或回滚。

## 验证

在 `tab` 运行 `pnpm test:newtab`、`pnpm build:only`。测试包含真实内存 SQLite 执行服务端查询/事务，以及本地持久化、空安装、旧表孤立记录、备注/图标/文件夹、多设备版本冲突、显式删除、历史版本、CAS 并发、上传中再次编辑、响应丢失重试、账户切换隔离和多页面增量合并。

在 `tmarks` 运行 `pnpm build:deploy`，以及 `WRANGLER_LOG_PATH=/tmp/tmarks-wrangler-build.log pnpm exec wrangler pages functions build functions --outdir /tmp/tmarks-functions`。这些命令只构建，不部署。额外对 Functions 单独运行 TypeScript 检查时，现有认证中间件和 API Key 生成器存在 Cloudflare/DOM 类型冲突等错误；常规网站、扩展和 Worker 构建通过。未进行线上同步或浏览器安装验收。

兼容的旧恢复接口 `/api/tab/newtab/sync` 保留，旧客户端空列表上传仍为无操作。网站的上游默认扩展下载包不会自动变成本地新构建的 `tab/dist`；测试请重新加载该目录。
